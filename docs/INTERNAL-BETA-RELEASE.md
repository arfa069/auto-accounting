# 自动记账内测发布包与 QA 指标规范

本文档定义 `auto-accounting` Android 客户端与后端在 Phase 2 内测阶段的发布、验证、指标与风险记录方式。

## 2. 手工 QA 脚本

### 2.1 账号与本地模式
1. 清空应用数据后启动 App，确认可进入本地模式。
2. 在“我的”页进入“账户管理”并登录测试账号，确认登录后显示账号信息。
3. 登录后确认可继续访问云端 AI、云端配置与账号删除状态。

### 2.2 通知捕获
1. 从“自动记账”页开启通知监听，确认跳转到系统设置并能回流更新状态。
2. 发送真实格式的微信/支付宝支付通知。
3. 确认“待确认”队列新增条目，金额、来源、商户名与证据原因正确。

### 2.3 账单同步
1. 从“待确认”的“补录账单”入口授予无障碍权限。
2. 手动发起微信/支付宝账单同步。
3. 确认历史账单补充进入“待确认”队列。

### 2.4 自动记账
1. 在“分类规则”页确认初始规则可见；再进入“自动记账”页开启自动记账和无障碍权限，不执行手动账单同步。
2. 在自动记账页检查后台运行、自启动、电池优化和省电模式引导；这些建议项不得阻断启用。Android 13 及以上在开启自动记账时按需处理结果通知授权，拒绝后仍继续采集与持久化。
3. 把本应用留在后台后完成一笔受控小额支付，确认收到脱敏结果通知；微信节点为空时确认 Android 11 及以上走本机瞬时 OCR。截图始终不留存，OCR 原文不进入待确认或账本；只有另行开启诊断日志且命中支付边界时才加密留存。点击通知进入对应待确认项；再关闭自动记账并确认后续页面不再采集。

### 2.5 待确认队列
1. 确认一笔交易，验证其进入账本。
2. 忽略一笔交易，验证其从主队列移除。
3. 从忽略列表恢复一笔交易，验证其回到主队列。
4. 验证相似交易去重提示与人工拆分/保留流程。

### 2.6 账本与报表
1. 用商户关键字和分类筛选账本。
2. 点击账目确认直接进入编辑页，保存后返回账本；确认编辑页不显示“新建资金账户”，删除仍可进入最近删除并撤销。
3. 使用“上一月/下一月”切换有账目的月份，验证月汇总和列表同步变化。
4. 验证报表中的分类占比、七个月现金流与排名。

### 2.7 云端 AI
1. 关闭 AI 同意后请求分类建议，确认被前端拦截。
2. 开启 AI 同意并请求分类，确认建议返回且只记录最小必要日志。
3. 开启增强上下文后再次请求，确认请求允许附带 note / evidence。

### 2.8 备份与恢复
1. 导出加密备份，设置大于 8 位的密码。
2. 删除本地数据后导入备份，验证账本、待确认队列、规则与设置恢复。
3. 使用错误密码导入，确认解密失败且不破坏现有数据。

### 2.9 账号删除
1. 发起账号注销，确认进入 7 天冷静期。
2. 冷静期内尝试写云端配置和请求 AI，确认返回 `ACCOUNT_DELETION_PENDING`。
3. 取消注销，确认云端写入恢复正常。

### 2.10 合规页面
1. 启动协议、登录/注册页和“合规与隐私”页均能访问隐私材料。
2. 在“合规与隐私”页分别打开隐私政策、个人信息收集清单、第三方服务清单和权限说明；确认商店审核说明不作为普通用户内容出现。
3. 在 Debug 包中从“合规与隐私”进入开发者工具；在 Release 包中确认该入口、设备矩阵和内测指标不显示。两种构建都应显示独立“诊断日志”入口。

### 2.11 诊断日志

1. Debug 首次安装默认开启；Release 首次安装默认关闭，开启前必须显示记录字段、用途、10 MB 上限、保留/清空方式、设备内加密和导出风险说明。
2. 用受控支付通知、支付结果页和补录会话验证通知/OCR 文字、商户、备注、账号、支付方式、订单号、采集证据和异常可在解锁后查看；普通通知、聊天、付款发起和无关页面不得保存正文。
3. 敏感内容默认遮罩。确认显示后将应用切到后台或离开页面，返回时必须重新遮罩；显示期间系统截图和最近任务缩略图应受 `FLAG_SECURE` 保护。
4. 使用至少 8 位且二次确认的临时口令导出 `.aadiag`；用 `tools/decrypt-diagnostics.ps1` 验证正确口令可得到 UTF-8 JSONL，错误口令不产生输出。
5. 关闭开关后确认历史仍可查看且不再新增事件；二次确认清空后确认分段和 Keystore key 已删除。不要在测试记录中粘贴解密后的敏感正文。

## 3. 质量指标计划

### 3.1 捕获准确率
- 公式：`确认入账条目数 / 实际支付条目数`
- 记录：按周对比微信/支付宝真实账单导出与应用账本。

### 3.2 去重准确率
- 公式：`正确合并的推荐数 / 总推荐数`
- 记录：追踪“建议合并”条目的最终人工决策。

### 3.3 审核效率
- 公式：`待确认页总操作耗时 / 完成处理的条目数`
- 记录：统计待确认页打开到确认/忽略完成的平均时长。

### 3.4 权限保留率
- 记录：每天启动时检查通知监听与无障碍权限状态，统计被系统回收的频次。

## 4. 构建与发布规范

### 4.1 命令
```powershell
.\gradlew.bat --no-daemon :apps:android:testDebugUnitTest
.\gradlew.bat --no-daemon :apps:android:assembleDebug
.\gradlew.bat --no-daemon :apps:android:assembleRelease
.\gradlew.bat --no-daemon :services:backend:test
```

### 4.2 产物路径
- Debug APK：`apps/android/build/outputs/apk/debug/android-debug.apk`
- 已签名 Release APK：`apps/android/build/outputs/apk/release/android-release.apk`
- 未签名 Release APK：`apps/android/build/outputs/apk/release/android-release-unsigned.apk`

### 4.3 命名建议
- 内测分发命名：`auto-accounting-v1.0.0-beta-YYYYMMDD.apk`

### 4.4 签名假设
- `assembleDebug` 使用默认 `debug.keystore`，仅用于开发验证。
- `assembleRelease` 始终完成编译、lint 和 APK 打包；只有 `apps/android/release.jks` 存在且 `RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` 均由本地属性或环境变量提供时，才会生成已签名的 `android-release.apk`。
- 缺少任一签名条件时，构建生成 `android-release-unsigned.apk`；该产物不得安装或分发。不得将签名材料或密码提交到仓库。
- 历史签名 APK 与 Debug 包签名身份不同，替换安装前必须备份数据并按设备提示进行全新安装。

## 5. 合规核对清单

- 隐私政策页可从启动协议、登录/注册页和“合规与隐私”页访问。
- 个人信息收集清单与第三方服务清单与当前实现一致。
- 通知监听、无障碍、后台监测相关权限边界有清晰说明。
- Android 13 及以上在开启自动记账时按需申请记账结果通知权限；拒绝后不影响本地采集，锁屏内容不显示金额、商户或交易对方。
- 本地删除与账号删除分开呈现，冷静期说明准确。
- 云端 AI 为显式同意开关，增强上下文为单独开关。
- Release 敏感诊断日志默认关闭且需知情同意；日志不上云、不进入备份，截图不保存，普通通知/聊天不保存正文，认证秘密始终脱敏。
- 诊断日志清空与本机数据删除覆盖密文和 Keystore key；已导出到 Downloads 的 `.aadiag` 文件需明确提示用户自行管理和删除。

## 6. 已知风险

- 真机 ROM 的后台限制与权限回收策略仍需要按设备矩阵逐台验证。
- Xiaomi Android 16 / MIUI `V816` 上，普通进程回收后无障碍服务可保持启用和绑定，但强制停止会移除本应用无障碍授权，必须由用户在系统界面重新授权。应用已修正将 `onInterrupt()` 误判为解绑的问题；真机复验确认系统重新绑定后页面不再误报“无障碍服务未连接”。使用 UIAutomator dump 会临时销毁并重建其他无障碍服务，权限健康验证应改用系统状态与普通截图，避免由验证工具制造短暂断开。
- 微信/支付宝页面结构变动仍可能影响通知解析、支付结果自动捕获与手动账单同步稳定性；当前策略优先读取无障碍节点，微信空节点页仅在 Android 11 及以上使用本机瞬时 OCR，并在字段不足时拒绝创建记录，不扩大到聊天或付款发起页面。
- 支付宝转账类真实通知已在 Xiaomi Release 包上复验入队，补丁 Release 已正确显示 `0.01` 元测试转账；金额解析已修正为优先使用带 `¥`、`￥` 或 `元` 的金额，避免把余额等后续数字误当交易金额。Issue 16 已实现应用内支付结果页面的无障碍自动捕获，微信商户支付和转账已完成真机验证；微信发送红包没有独立结果页，不从付款发起页或聊天页推断成功，钱包账单/红包记录验证因隐私影响列为默认不执行的可选项。
- 本机已有发布 keystore，且可在本地签名环境恢复后构建已签名 Release；签名材料和密码均不得提交到仓库。新 PowerShell 会话若未重新加载本地签名环境，不能据此误判为项目无法生成已签名 Release。支付通知、无障碍滚动和锁屏保活仍依赖真机场景验证。
- `.aadiag` 和解密后的 JSONL 包含敏感交易上下文；即使应用内和导出均加密，也必须限制接收人、保存位置和保留时长，排障结束后由用户或操作者自行删除 Downloads 与明文副本。

## 7. 内测退出标准

- 后端测试与 Android 单测全部通过。
- Debug 与 Release 构建产物都能生成。
- 设备矩阵中的关键 ROM 至少完成一轮核心路径手工验证。
- 所有阻塞项、未验证项与签名限制被显式记录。
- 合规页面与关键中文文案在测试包内可正常阅读。

## 8. 受限手工检查

- 真实支付通知拦截：必须在真机上完成。
- 锁屏保活与 ROM 清后台：必须在真机上完成。
- 微信/支付宝真实支付结果自动捕获、结果通知和跨来源去重：必须在真机上完成。
- 微信/支付宝真实账单同步滚动：作为历史补录兜底，必须在真机上完成。
- 已签名 beta 分发包：已成功重建并通过 v2 签名校验，并在 Xiaomi 设备完成全新安装和冷启动；完成目标 ROM 的核心链路前不得分发。
