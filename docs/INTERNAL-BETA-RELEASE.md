本文档定义 `auto-accounting` Android 客户端与后端在 Phase 2 内测阶段的发布、验证、指标与风险记录方式。

## 2. 手工 QA 脚本

### 2.1 账号与本地模式
1. 清空应用数据后启动 App，确认可进入本地模式。
2. 在“我的”页登录测试账号，确认登录后显示账号信息。
3. 登录后确认可继续访问云端 AI、云端配置与账号删除状态。

### 2.2 通知捕获
1. 从权限中心开启通知监听，确认跳转到系统设置并能回流更新状态。
2. 发送真实格式的微信/支付宝支付通知。
3. 确认“待确认”队列新增条目，金额、来源、商户名与证据原因正确。

### 2.3 账单同步
1. 从同步入口授予无障碍权限。
2. 手动发起微信/支付宝账单同步。
3. 确认历史账单补充进入“待确认”队列。

### 2.4 自动记账
1. 在“我的”页确认初始分类规则可见，再开启“自动记账”和无障碍权限；不执行手动账单同步。
2. 单独授权“记账结果通知”，把本应用留在后台后完成一笔受控小额支付。
3. 在来源应用的支付成功页确认收到脱敏结果通知，点击通知进入对应待确认项；再关闭自动记账并确认后续页面不再采集。

### 2.5 待确认队列
1. 确认一笔交易，验证其进入账本。
2. 忽略一笔交易，验证其从主队列移除。
3. 从忽略列表恢复一笔交易，验证其回到主队列。
4. 验证相似交易去重提示与人工拆分/保留流程。

### 2.6 账本与报表
1. 用商户关键字和分类筛选账本。
2. 验证报表中的分类占比、月趋势与排名。

### 2.7 云端 AI
1. 关闭 AI 同意后请求分类建议，确认被前端拦截。
2. 开启 AI 同意并请求分类，确认建议返回且只记录最小必要日志。
3. 开启增强上下文后再次请求，确认请求允许附带 note / evidence。

### 2.8 备份与恢复
1. 导出加密备份，设置 8 位以上密码。
2. 删除本地数据后导入备份，验证账本、待确认队列、规则与设置恢复。
3. 使用错误密码导入，确认解密失败且不破坏现有数据。

### 2.9 账号删除
1. 发起账号注销，确认进入 7 天冷静期。
2. 冷静期内尝试写云端配置和请求 AI，确认返回 `ACCOUNT_DELETION_PENDING`。
3. 取消注销，确认云端写入恢复正常。

### 2.10 合规页面
1. 启动协议、登录/注册页与“关于/隐私政策”入口都能访问隐私材料。
2. 权限说明、个人信息清单、第三方服务清单与账号删除说明可正常阅读。

## 3. 质量指标计划

### 3.1 捕获准确率
- 公式：`确认入账条目数 / 实际支付条目数`
- 记录：按周对比微信/支付宝真实账单导出与应用账本。

### 3.2 去重准确率
- 公式：`正确合并的推荐数 / 总推荐数`
- 记录：追踪“建议合并”条目的最终人工决策。

### 3.3 审核效率
- 公式：`待确认页总操作耗时 / 完成处理的条目数`
- 记录：统计待确认页打开到确认/忽略完成的平均时长。

### 3.4 权限保留率
- 记录：每天启动时检查通知监听与无障碍权限状态，统计被系统回收的频次。

## 4. 构建与发布规范

### 4.1 命令
```powershell
.\gradlew.bat --no-daemon :apps:android:testDebugUnitTest
.\gradlew.bat --no-daemon :apps:android:assembleDebug
.\gradlew.bat --no-daemon :apps:android:assembleRelease
.\gradlew.bat --no-daemon :services:backend:test
```

### 4.2 产物路径
- Debug APK：`apps/android/build/outputs/apk/debug/android-debug.apk`
- Release APK 产物：`apps/android/build/outputs/apk/release/android-release.apk`

### 4.3 命名建议
- 内测分发命名：`auto-accounting-v1.0.0-beta-YYYYMMDD.apk`

### 4.4 签名假设
- `assembleDebug` 使用默认 `debug.keystore`，仅用于开发验证。
- `assembleRelease` 只有在本地签名配置齐备且密码匹配时才能生成 release APK；不得将签名材料或密码提交到仓库。
- `2026-07-10` 本机内测签名已重新配置，`assembleRelease` 可生成通过 v2 签名校验的 APK。该签名身份与先前的 Debug 包不同，必须以全新安装方式替换；Xiaomi 设备已在保留加密备份后完成该替换。

## 5. 合规核对清单

- 隐私政策页可从启动协议、登录/注册页和“关于”页访问。
- 个人信息收集清单与第三方服务清单与当前实现一致。
- 通知监听、无障碍、后台监测相关权限边界有清晰说明。
- 记账结果通知权限独立申请，拒绝后不影响本地采集，锁屏内容不显示金额、商户或交易对方。
- 本地删除与账号删除分开呈现，冷静期说明准确。
- 云端 AI 为显式同意开关，增强上下文为单独开关。

## 6. 已知风险

- 真机 ROM 的后台限制与权限回收策略仍需要按设备矩阵逐台验证。
- 微信/支付宝页面结构变动仍可能影响通知解析、支付结果自动捕获与手动账单同步稳定性；当前策略会在字段不足时拒绝创建记录，不扩大到聊天或付款发起页面。
- 支付宝转账类真实通知已在 Xiaomi Release 包上复验入队，补丁 Release 已正确显示 `0.01` 元测试转账；金额解析已修正为优先使用带 `¥`、`￥` 或 `元` 的金额，避免把余额等后续数字误当交易金额。Issue 16 已实现应用内支付结果页面的无障碍自动捕获，但支付宝商户扫码 / 碰一碰和微信扫码、转账、红包仍需逐类真机确认节点是否可访问。
- Release 构建和签名不再受本地 keystore 密码阻塞；Xiaomi 设备已在保留加密备份后完成 Release 全新安装及冷启动。未来设备替换仍应先备份数据，并明确确认会清除旧签名安装的数据。支付通知、无障碍滚动和锁屏保活仍依赖真机场景验证。

## 7. 内测退出标准

- 后端测试与 Android 单测全部通过。
- Debug 与 Release 构建产物都能生成。
- 设备矩阵中的关键 ROM 至少完成一轮核心路径手工验证。
- 所有阻塞项、未验证项与签名限制被显式记录。
- 合规页面与关键中文文案在测试包内可正常阅读。

## 8. 受限手工检查

- 真实支付通知拦截：必须在真机上完成。
- 锁屏保活与 ROM 清后台：必须在真机上完成。
- 微信/支付宝真实支付结果自动捕获、结果通知和跨来源去重：必须在真机上完成。
- 微信/支付宝真实账单同步滚动：作为历史补录兜底，必须在真机上完成。
- 已签名 beta 分发包：已成功重建并通过 v2 签名校验，并在 Xiaomi 设备完成全新安装和冷启动；完成目标 ROM 的核心链路前不得分发。
