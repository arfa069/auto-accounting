# 实时捕获微信/支付宝支付结果并反馈记账状态

> 2026-07-17 隐私合同更新：本文中“OCR/页面原文不写日志”的表述继续适用于普通业务日志与账本数据库；用户另行主动开启的设备内加密敏感诊断日志是受控例外。截图仍永不保存，普通通知/聊天不记录正文，认证秘密始终脱敏。当前规则以 `docs/COMPLIANCE.md` 和 `docs/research/auto-bookkeeping-flow.md` 为准。

## 当前状态

本 Issue 的当前设备验收已完成：无障碍节点主链路和微信空节点页面的受限本地 OCR 兜底已实现；支付宝商户支付、支付宝转账、微信商户支付和微信转账成功页已通过真机验证。微信发送红包不存在独立成功页，已明确不通过付款发起页或聊天页推断成功。

Issue 16 原方案把“用户点击账单同步，再手动打开交易详情”作为主要路径，只能补录历史账单，不符合自动记账的核心流程。此前已经完成的页面解析、去重和安全过滤可作为实现基础，但不能视为本 Issue 的功能验收结果。

## 目标

用户一次性开启“自动记账”并授予无障碍权限后，正常使用微信或支付宝完成支付。应用应优先读取支付成功页、交易结果页或随后自然出现的支付记录页的无障碍节点；微信页面未提供可读节点时，可在严格边界内使用本机瞬时截图 OCR。随后完成解析、去重、分类和持久化，并通过本应用的系统通知告知处理结果。

主流程不得要求用户返回本应用、点击“账单同步”或再次进入账单详情。

## 用户主流程

1. 用户在本应用中明确开启“自动记账”，按引导授予无障碍权限；Android 13 及以上在开启时按需申请结果通知权限。
2. 用户正常使用微信或支付宝付款，本应用不参与、不点击也不改变付款流程。
3. 来源应用显示支付成功页、交易结果页或其他受支持的支付记录页面。
4. 无障碍服务收到允许包名的窗口事件，等待页面内容短暂稳定后优先读取可访问节点文本和内容描述；Android 11 及以上的微信页面节点为空时，才截取一帧在本机 OCR，处理后立即释放图片。
5. 本地流水线依次执行页面识别、字段解析、标准化、去重和分类建议。
6. 处理结果只能是以下之一：
   - 信息完整且命中本地规则：创建一条带分类建议的待确认记录。
   - 信息完整但未命中规则：创建一条未分类的待确认记录。
   - 命中已有交易：合并证据或标记重复，不创建第二条待确认记录。
   - 页面不受支持、字段不足或状态不明确：不猜测、不创建部分账目，记录脱敏失败原因。
7. 本应用发布结果通知，例如“识别到 1 笔账目，待确认”或“已归类为餐饮，待确认”；点击通知进入对应待确认项。

## 分类规则约束

当前通知采集和无障碍账单采集在识别成功后都会读取本地分类规则，并在创建待确认记录前应用分类建议：

- App 首次安装后必须在 `categorization_rules` 表中写入一组可见、可编辑的初始规则，不能以空规则表作为正常首次使用状态。
- 规则可按商户/标题包含文本、来源应用和交易类型进行匹配。
- 只使用已启用且分类非空的规则；多条规则命中时，优先级更高者优先，优先级相同时使用最近更新者。
- 命中规则只预填待确认记录的分类，不执行确认入账。
- 未命中规则时仍创建待确认记录，由用户补充或修改分类。
- AI 分类仍只提供建议，不能绕过待确认队列。

Issue 16 继续遵守现有 PRD 约束：所有自动捕获交易必须先进入待确认队列，只有用户确认后才能写入账本。

## 初始规则初始化

- 初始规则与用户新建规则存放在同一张 `categorization_rules` 表中，界面展示真实数据库记录，不维护不可见的硬编码规则副本。
- 初始规则使用稳定 ID，并记录初始化版本；首次安装和现有用户升级时各执行一次幂等初始化。
- 用户可以编辑、停用或删除初始规则；应用重启或普通版本升级不得覆盖用户修改，也不得复活用户已删除的规则。
- “清除本地数据”属于恢复出厂状态，完成后应重新生成当前版本的初始规则。
- 初始规则只提供分类建议，因此可以覆盖常见的餐饮、交通、购物、居住、医疗健康、工资和退款场景，但必须采用明确关键词或交易类型，避免一条过宽规则匹配全部支出或收入。
- 当前 Release 已完成规则初始化；全新安装和旧库首次升级都会生成同一组可见规则，且不会覆盖用户后续修改。

## 采集边界

优先支持：

- 微信、支付宝原生支付成功页和交易结果页。
- 用户付款后来源应用自动展示的交易详情或支付凭证页。
- 用户之后自然打开的支付宝 `消息 -> 消息盒子 -> 支付信息`、账单详情。
- 已有系统支付通知采集作为独立并行来源，所有来源进入同一去重语义。

微信钱包账单、红包记录或交易详情可能涉及更大范围的历史交易隐私，默认不读取、不验证，也不纳入当前自动捕获白名单。是否开展受限真机验证记录在 [可选真机验证清单](./OPTIONAL-VALIDATIONS.md)，需产品负责人另行决定。

默认使用 Android 无障碍节点树。仅当用户已开启自动记账、当前包名为微信、节点文本为空、屏幕已解锁且系统为 Android 11 及以上时，允许截取一帧并使用随 App 打包的本地 OCR；Android 14 及以上只截当前应用窗口，Android 11-13 使用整屏截图接口。图片不保存、不上传，OCR 原文不进入账本；仅在用户另行开启的本机加密敏感诊断日志中按支付/补录边界留存文字。识别后仍必须通过支付完成状态、明确金额和安全排除规则。支付宝及有可读节点的页面不走 OCR。

## 权限与开关

- “自动记账”是用户可随时关闭的持久化开关；关闭后无障碍事件不得进入解析流水线。
- 无障碍权限是实时页面采集的必要条件，但不应要求用户先完成一次手动账单同步。
- 通知监听权限只负责读取来源应用实际发布的支付通知，不应成为无障碍实时采集的前置条件。
- 本应用发布处理结果需要独立的通知权限和通知渠道；Android 13 及以上未授权时，账目仍应正确持久化，只是不发布结果通知。
- 权限被撤销、服务断开或 ROM 阻止后台运行时，应用应显示真实状态，不得仍显示“自动记账运行中”。

## 安全护栏

- 只接受 `com.tencent.mm` 和 `com.eg.android.AlipayGphone`。
- 必须同时满足受支持页面特征、完成/成功状态和必要交易字段，不能只凭金额或“支付”单个关键词入账。
- 明确排除聊天、普通消息、通讯录、付款发起、收银台、密码输入、转账发送、红包发送、退款发起等页面。
- 服务只能被动观察，不执行点击、滚动、输入、返回、跳转、付款、转账、退款或发送消息。
- 原始页面文本、金额、商户、对方和账号信息不得写入普通日志或 Logcat；仅用户主动开启的设备内加密敏感诊断日志可按既定支付/补录边界记录，认证秘密必须先脱敏。
- OCR 截图只存在于内存并在识别后立即释放，OCR 原文不写入数据库；待确认项只保留解析后的必要结构化字段。
- OCR 丢失币种符号时，只允许使用版面中字号明显最大的纯数字金额行补全人民币符号；候选不突出、存在同等候选或缺少支付完成状态时安全失败。
- 页面连续刷新产生的多次事件必须经过稳定窗口、会话内防抖和持久化去重，不能重复通知或重复记账。
- 通知监听与无障碍 OCR 可能同时到达；两条采集链必须共享同一个持久化互斥区，不能各自读取旧队列后分别写入。

## 结果通知

- 建立低打扰的“记账结果”通知渠道，区分未分类待确认、已分类待确认、重复合并和识别失败。
- 锁屏默认只显示通用结果，不显示金额、商户或交易对方；敏感详情只在用户解锁并进入应用后展示。
- 结果通知点击后打开对应待确认项；任何结果通知都不能直接确认入账。
- 同一交易被通知监听与无障碍先后识别时，只更新既有记录，避免重复成功通知。
- 短时间内多笔交易可合并通知，防止页面事件抖动造成通知轰炸。

## 非目标

- 不自动操作微信或支付宝，也不绕过权限、账号保护或支付安全页面。
- 不读取聊天、普通消息或与交易无关的页面。
- 不把手动“账单同步”作为实时自动记账的必经步骤；它只保留为历史补录和故障兜底能力。
- 不录屏，不持久化或上传截图，不使用云端 OCR，不引入悬浮窗或 VPN/网络抓包。
- 不自动确认或写入账本，本地规则和 AI 都只能提供分类建议。
- 不上传原始支付页面内容；现有明确授权的 AI 分类路径仍只发送其允许的最小字段。

## 验收缺口复查

截至 `2026-07-11`，支付宝商户支付与转账、微信商户支付与转账的实时捕获主链路均已有真机证据；通知与无障碍并发去重、待确认落库、微信空节点 OCR、同页防重复和关闭自动记账阻断采集也已完成复验。微信发送红包因来源应用不存在独立成功页而明确不支持，不再要求为验收制造新的真实付款。

剩余验证按风险处理：

- **已处理的来源覆盖**：支付宝商户支付、支付宝转账、微信商户支付和微信转账均已有真机结果页证据；这些入口共用相同的来源白名单、完成状态判断、字段解析、待确认持久化和共享去重协调器。微信发送红包不存在独立结果页，已明确不支持实时捕获。
- **已处理的跨来源去重**：通知、结果页、支付信息和账单详情均通过同一 `BillSyncPipeline`、`DedupeEngine` 与 `ReviewQueueCaptureCoordinator` 入队；通知与无障碍并发真机复验已确认只保留一条待确认，消息盒子/账单详情不需要为验证目的读取真实隐私内容。
- **已处理的通知权限边界**：结果通知权限撤销和恢复授权已在 Android 13 以上设备验证；当前在开启自动记账时按需申请，采集处理器在通知器之前完成待确认持久化，完整自动化测试覆盖拒绝不阻断边界。
- **真机破坏性操作不执行**：清除本地数据后恢复初始规则已由自动化测试覆盖；为了保护当前测试数据，不在设备上执行清除操作。
- **缺少目标设备**：Android 11-13 的整屏截图 OCR 仅有代码和自动化边界测试，仍缺对应系统版本真机证据。
- **默认不执行**：微信钱包账单、红包记录和交易详情的节点检查因历史交易隐私影响保留在可选清单；聊天内容不读取、不截图、不作为验证材料。

## 手工验证

1. 全新安装后先确认分类规则页面已展示可编辑的初始规则，再授予无障碍权限并开启自动记账；Android 13 及以上按开启流程处理结果通知授权，然后把本应用退到后台。
2. 完成一笔支付宝商户扫码或碰一碰支付，不返回本应用，确认支付结果页自然触发一条正确的待确认通知。
3. 分别验证支付宝转账、微信扫码支付和微信转账的实际结果页；微信空节点页应触发本地 OCR，只记录脱敏后的来源、页面类型和处理状态。
4. 打开同一交易的来源通知、消息盒子或账单详情，确认只合并证据，不重复记账或重复通知。
5. 打开聊天、普通消息、付款发起、密码和转账/红包发送页，确认待确认数和账本数均不变化。
6. 关闭自动记账后重复打开支付记录页，确认不再采集；重新开启后恢复受支持页面采集。
7. 分别拒绝结果通知权限、撤销无障碍权限、锁屏和重启设备，验证持久化、状态提示与 MIUI 后台行为符合预期。

## 回滚或安全说明

- 实时采集必须受持久化功能开关控制；出现误采集时可通过关闭开关立即停止，不影响已有账本。
- 新页面识别采用窄白名单和完整字段校验；来源应用 UI 变化时宁可漏记，不得放宽到聊天或普通消息。
- 分类规则异常或匹配错误只允许影响待确认项的建议分类，不能直接改变账本。
- 若无障碍节点和受限本地 OCR 均无法取得完整必要字段，应保留通知监听和手动历史补录兜底并安全失败，不得继续扩大读取范围。

Issue 16 采用以下推荐默认值：

1. **通知隐私**：锁屏默认隐藏金额和商户，解锁后点击通知查看详情。
2. **手动账单同步定位**：保留为历史补录/故障兜底，但从自动记账主流程和连续监控前置条件中移除。
3. **权限关系**：通知监听和无障碍实时采集互相独立，任一来源可单独工作，再由统一去重处理重叠交易。
4. **微信空节点兜底**：只在 Android 11 及以上、自动记账已开启、微信节点文本为空时使用本机瞬时 OCR；图片始终不保存，OCR 原文不进入待确认或账本，仅可在用户另行开启的加密敏感诊断日志中按支付/补录边界留存；所有识别结果仍先进入待确认。

以上流程保持现有 PRD 和架构中的待确认约束，不引入自动确认入账能力。
