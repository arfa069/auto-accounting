# 进行中：增加账户级自动多端账本同步

## 目标

在已验证登录账号下提供自动双向同步：Room 保持离线可写，后端成为该账号多设备共享的同步中心；冲突、注销和换账号均不得静默覆盖或泄露另一账号数据。

## 范围

- 同步账本、正式及最近删除账目、分类、资金账户和分类规则。
- 使用类型化共享契约、数据库 v7、Room v8、持久化 outbox、记录级版本、增量游标、删除墓碑和人工冲突。
- 登录验证、回到前台、同步范围数据变化、手动重试和每 15 分钟周期任务触发同步。
- “数据与备份”提供首次告知、状态、待上传数量、立即同步、HTTP 风险和冲突处理。
- 账号合并迁移不同记录并把同记录不同版本变为冲突；最终注销清理全部云端同步状态。

## 非目标

- 不同步待确认、已忽略、采集证据、当前账本选择、权限/监控设置、诊断日志或备份文件。
- 不使用 WebSocket，不阻塞离线记账，不把无效 Session 解释为删除本机数据。
- 不为生产同步放宽 HTTPS；局域网 HTTP 只允许本地显式开关和回环/RFC1918 地址。

## 目标文件或模块

- `shared/api`：同步 Payload、分页、幂等、墓碑、冲突和稳定错误契约。
- `services/backend`：数据库 v7、Store/Service/JDBC/Route、注销与账号合并生命周期。
- `apps/android`：Room v8、Repository/outbox、远端应用器、WorkManager、首次绑定/换账号和 Compose UI。
- `docs`：ADR 0059、现行产品/架构/UI/合规文档与本 Issue。

## 验收标准

- [x] 账目同步契约不包含设备采集证据，JSON 编解码对称，单批最多 100 条且请求体最多 1 MiB。
- [x] 后端按账号隔离，支持幂等 push、snapshot/pull、删除墓碑、版本冲突、冲突解决、冷静期只读和最终清理。
- [x] Room v7→v8 保留既有数据，旧资金账户在迁移事务中回填唯一 `syncId`，四张同步表与 schema 8 已登记。
- [x] 同步范围内的 Repository 写入与 outbox 同事务；远端应用不会反向生成 outbox，离线或 Session 未验证时保留待上传数据。
- [x] 分类和资金账户使用云端规范 ID 并重映射引用；未编辑的内置分类/规则在首次同步时采用云端版本而不制造冲突，真实同记录并发更新进入人工冲突，同名不同 ID 账本均保留。
- [x] WorkManager 使用唯一立即任务和唯一 15 分钟周期任务，并以进程互斥避免并发应用同一游标。
- [x] 首次启用明确说明同步范围、服务端可读存储、HTTPS 和注销影响；双边非空时确认合并。
- [x] 换账号前阻止未清空 outbox，并在单个 Room 事务中替换正式同步范围；目标账号为空时只创建空默认账本。
- [x] 默认 HTTPS；显式 HTTP 测试开关仅允许回环/RFC1918，并持续展示未加密风险。
- [ ] 两台真实设备完成新增、编辑、离线冲突、删除/恢复、签出恢复及账号切换验收。
- [ ] 生产式 HTTPS Release 环境完成同步验收；受控局域网 HTTP Release 完成风险提示与功能验收。

## 自动化验证

- `shared/api`：契约对称、缺失字段、非法删除形状及规范 ID 重映射。
- Backend：H2 v6→v7、重复迁移、事务回滚、幂等、分页、冲突、账号隔离、Route 鉴权/大小限制、注销和账号合并。
- Android：Room 迁移、outbox 原子性、规范 ID 重映射、冲突、账号切换回滚、HTTP 限制、WorkManager 和 Compose 多宽度/大字体。
- 最终验证命令与实际结果在完成全量测试后补入“验证记录”。

## 手工验证

1. 完全卸载后全新安装 Release，登录已有云端数据的账号并启用同步；未编辑的系统分类和初始分类规则不产生冲突。
2. 设备 A 新增账目，设备 B 自动收到；B 编辑后 A 收到。
3. 两台设备离线编辑同一账目，联网后出现冲突，并分别验证保留云端/本机。
4. 删除、恢复及 30 天永久清理不会被离线旧设备复活。
5. 签出停止上传，重新登录同一账号恢复；换账号不会出现上一账号正式数据。
6. Release HTTPS 同步成功；显式测试开关下局域网 HTTP 可用且显示风险提示。

## 回滚说明

关闭客户端同步只解除本机绑定并保留本机账本；不得降级 Room 或后端数据库。需要停止服务端能力时先禁用路由/调度并保留 v7 表，待确认所有客户端 outbox 已处理后再制定单独的数据迁移方案。
