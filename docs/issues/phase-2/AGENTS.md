# Phase 2 Issue 指南

## 用途

每个文件应是可独立领取、可验证、可回滚的纵向任务切片。依赖未解除时不得把任务写成可并行实施。

## 固定结构

沿用现有章节：目标、范围、非目标、目标文件或模块、验收标准、验收测试、手工验证、回滚或安全说明、验证记录、依赖。

## 编写与更新规则

- 范围应覆盖一条可工作的用户或系统链路，避免仅按技术层拆成互相不可验证的半成品。
- 验收标准写可观察结果；验收测试写具体命令、测试类或设备步骤，不使用“确保正常”等模糊表述。
- 涉及权限、删除、迁移、账号或敏感数据时，明确失败路径、数据影响和回滚方式。
- 只有实际执行验证后才能填写通过记录；注明命令、结果及未执行项目。
- 新增、完成、阻塞或调整依赖时，同步更新 `docs/issues/phase-2/README.md` 和相关 Phase 2 汇总文档。

## 验证

检查编号、链接、依赖方向和索引一致性，并运行 `git diff --check -- docs/issues/phase-2/`。
