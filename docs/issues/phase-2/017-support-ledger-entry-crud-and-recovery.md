# 实现单笔账新增、查看、编辑、删除与恢复

## 目标

补齐账本记录的完整单笔生命周期：用户可以手动新增账目、查看详情、编辑手动或自动捕获后确认的账目、软删除并在 30 天内恢复，同时保证 Room、报表、加密备份和本地数据删除使用同一份持久化真相。

## 范围

### 数据模型与迁移

- 新增独立的资金方向：流入、流出、不计收支；金额继续使用正的最小货币单位整数。
- 将账目当前支付来源与原始采集来源、录入方式分开；手动账目的支付来源可以为空。
- 账本记录保留创建或首次确认时间、最后修改时间、可空删除时间，以及自动捕获时可用的原待确认 ID、原始来源和采集证据。
- 资金账户允许支付来源为空，以支持现金、银行卡等用户创建账户。
- 提供连续、无损的 Room v4 到下一版本迁移并导出新 schema JSON；禁止使用破坏性迁移。

### 单笔账操作

- 手动新增直接写入账本，不经过待确认队列，也不执行重复检查。
- 详情页默认只读；手动和自动账目都能显式进入编辑模式。
- 新增和编辑共享表单，只有点击保存后才一次性校验并持久化；未保存退出需要确认。
- 删除将记录移出活动账本、搜索和报表，但保留相同记录 ID 与完整字段 30 天。
- 最近删除支持恢复、确认后永久删除，并在保留期届满后执行幂等清理。

### 表单与展示

- 必填：资金方向、交易类型、金额、交易时间。
- 可选：商户、现有分类、资金账户、备注、支付来源；共享表单统一显示“商户（可选）”，未选分类时使用未分类。
- 首版仅支持 CNY；金额必须大于零、最多两位小数且不能溢出最小货币单位整数；交易时间不能晚于当前设备时间。
- 资金账户选择器只列出现有账户；新账户统一从独立资金账户管理页创建。
- 自动账目允许修改当前支付来源及其他用户字段；原始采集来源、录入方式、原待确认 ID、生命周期时间和采集证据继续持久化，但当前账本 UI 不组合该调试信息区域。

### 报表、备份与清理

- 流入计入收入，流出计入支出，不计收支记录不进入收入、支出、净额和支出分类统计。
- 编辑、删除、恢复和永久删除后，账本与报表通过持久化流立即得到一致结果。
- 加密备份升级到能保存新增字段及最近删除记录的新格式，同时继续支持导入现有 V2 备份。
- V2 备份和 Room v4 旧记录迁移时保留现有报表语义：`INCOME`、`REFUND` 映射为流入，其余旧类型映射为流出。
- 旧记录无法可靠还原具体采集方式时使用明确的旧版未知来源状态，不伪造通知捕获或账单同步来源；原始支付来源可从旧 `source` 保留。
- 清除本地数据必须同时清除活动账目、最近删除账目及新增的账本元数据。

## 非目标

- 不包含分类的新增、编辑或删除。
- 不包含多币种、汇率换算、账户余额或对账。
- 不包含未来计划账目、周期账目或提醒。
- 不保留逐次编辑版本，也不提供历史差异或版本回滚。
- 不新增云端账本同步、后端接口或手动账目去重。

## 验收标准

### 新增与查看

- [x] 首页中央新增按钮可创建手动账目；合法数据保存一次后立即出现在账本和对应报表，重启后仍存在。
- [x] 新增不创建待确认记录、不运行重复检查，且允许与现有账目内容相同。
- [x] 必填、金额精度、金额范围、CNY 和未来时间校验失败时不产生部分记录或资金账户孤儿数据。
- [x] 点击账本行直接进入编辑表单；当前用户字段与原始采集信息在持久化模型中保持独立。

### 编辑与统计

- [x] 手动和自动账目均可编辑全部约定的用户字段，显式保存后以一个事务更新当前值和最后修改时间。
- [x] 自动账目修改支付来源后，原始采集来源、录入方式、原待确认 ID、首次确认时间和采集证据保持不变。
- [x] 返回脏表单时可继续编辑或放弃修改；放弃后数据库和报表均无变化。
- [x] 流入、流出、不计收支在月汇总、净额、分类支出和趋势中符合 PRD，编辑资金方向后统计立即重算。

### 删除与恢复

- [x] 删除确认说明 30 天可恢复；成功后记录不再出现在活动账本、搜索、筛选、CSV 和报表，并提供一次 Snackbar 撤销。
- [x] 最近删除入口显示删除时间和剩余天数，恢复后使用原记录 ID 和字段返回活动账本。
- [x] 永久删除需要二次确认且执行后不可恢复；到期清理可在应用启动或读取最近删除时幂等执行。
- [x] 已删除记录不会因编辑、筛选、报表观察或进程重启意外重新出现。

### 迁移、账户与备份

- [x] Room v4 升级保留全部账目和资金账户数据，旧账目统计结果在迁移前后保持一致，且新 schema JSON 已提交。
- [x] 内联创建资金账户会规范化空白名称、防止同一来源下重复创建，并允许支付来源为空；不产生余额或对账状态。
- [x] 新版加密备份往返保留活动/已删除状态、资金方向、当前与原始来源、时间戳和证据；现有 V2 备份仍能安全导入。
- [x] 备份解密、版本校验或字段校验失败时，在任何本地表被清除或修改前终止。
- [x] 清除本地数据后活动账本、最近删除和相关元数据全部为空，默认分类仍按既有规则恢复。

## 手工验证

1. 从首页中央新增按钮创建一笔现金支出和一笔收入，确认保存后进入账本，且列表、搜索、筛选和报表结果正确；强制停止并重启应用后复查。
2. 点击一笔自动捕获后确认的账目直接进入编辑页，修改金额、资金方向、支付来源和备注，确认持久化的原始采集信息未被覆盖。
3. 在编辑表单修改但不保存，分别验证继续编辑和放弃修改；确认放弃不会改变账本或报表。
4. 删除账目后验证 Snackbar 撤销；再次删除后从最近删除恢复；最后对测试记录执行确认永久删除。
5. 导出新版加密备份，在受控测试数据上完成删除后恢复；另用现有 V2 测试备份验证向后导入。

## 回滚或安全说明

- Room 迁移前使用测试数据库和脱敏备份验证；不得用 `fallbackToDestructiveMigration` 或删除旧库绕过失败。
- v4 到新版本升级后，旧 APK 不能安全打开新 schema；回滚应用版本前必须先用兼容备份恢复到受支持环境，不能直接覆盖安装假定可降级。
- 软删除期间保留的是敏感交易数据；最近删除详情、备份和日志继续遵守现有交易信息保护规则，日志不得包含金额、商户、备注或采集原文。
- 永久删除与到期清理必须限定单条或明确到期集合，并在事务内完成；不得误用全表删除。
- 新版备份导入必须先完整解密、解析和校验，再在一个事务中替换本地数据。
